# 개선 제안 — 하네스에서 비어 있는 곳

현재 하네스는 문서 3개(CLAUDE.md, story-service, story-work)로 이루어져 있다. 흐름과 역할 분리는 잘 잡혀 있고, 아래는 문서끼리 어긋나거나 비어 있는 부분이다.

## 1. 문서끼리 안 맞는 곳 (우선순위 높음)
- **대표 이미지 선택 기준이 없다.** story-work에서 가장 오래 고민한다고 적은 2번인데 CLAUDE.md에는 규칙이 없다. 제안: 기본값은 첫 번째 이미지, 에이전트가 후보 최대 3장을 제시하고 사람이 고른다. 선택은 승인 단계와 합친다.
- **"이미지가 어긋나지 않았는지"를 검증하는 게이트가 없다.** story-work 5번에 있는데 게이트 규칙은 글자만 다룬다. 제안: 이미지가 프레임 밖으로 나가지 않음, 비율 왜곡 0, 원본 가로 최소 1200px.
- **작업 기록의 위치와 형식이 없다.** 유저스토리 5번과 파이프라인 5번이 "기록"을 말하지만 파일명과 형식이 없다. 제안: `작업기록.md`에 `| 번호 | 제목 | 날짜 | 승인 |` 한 줄씩 추가.

## 2. 규칙은 있는데 확인 방법이 없다
- 게이트 5개 각각에 "무엇으로 확인하는지"를 적는다. 예: 크기는 Figma 프레임 속성, 잘림은 텍스트 노드 영역과 프레임 영역 비교, 줄 수는 텍스트 노드 줄 수.
- 3회 연속 실패 때 사람에게 알릴 내용을 정한다. 실패한 규칙 이름, 시도 횟수, 마지막 미리보기.

## 3. 빠진 예외 상황
- `영감N/`이 이미 있을 때: 덮어쓰지 않고 사람에게 묻는다.
- 포스트에 이미지가 0장일 때: 멈추고 알린다. 현재는 게이트에서야 걸린다.
- 제목이 2줄을 넘을 때: 에이전트가 줄인 제목안을 제안하고 사람이 고른다. 에이전트가 제목을 바꿔서 통과시키지 않는다.
- Threads 로그인이 필요할 때: 사람이 직접 로그인한다. 자격 증명은 기록하지 않는다.

## 4. 산출물과 구조
- 내보내기 규격: 파일명 `thumbnail.png`, PNG, 크기 1200x630 재확인.
- 기존 스킬 `bk-thread-thumbnail-maker`와의 관계를 CLAUDE.md에 한 줄로 적는다(수집·조립에 그대로 쓸지).
- `README.md`(한 장 요약), `.gitignore`(영감N 이미지 폴더), 통과·실패 예시 1건씩 추가.

## 5. 작업 순서 제안
1. 대표 이미지 규칙과 이미지 게이트 추가 (CLAUDE.md)
2. 게이트별 확인 방법 표 추가
3. 작업기록 형식 정의
4. 예외 상황 섹션 추가
5. README, 예시
